# 02 — A small idea from the owner that touches rough ground

**Prompt:** `/product I keep wanting to log something I did yesterday evening, and picking the date is clumsy`

(This maps to P-09, "Say when, beyond 2 days ago". The activity details screen and the When chips
are the adjacent ground.)

Checklist:
- [ ] A new `owner-notes.md` entry, with the owner's words quoted and the interpretation kept
      separate.
- [ ] Classified with the big/small rule, and the clause is written down. A date picker on an
      existing screen with no new stored field is **small**.
- [ ] Linked to the existing P-09 instead of creating a duplicate item.
- [ ] One `polish-scout` with the adjacency brief. Its report lists what the feature touches
      (activity details, the When chips, sorting on Home and Activities, export) and classifies each
      rough spot as blocks, drags or unrelated.
- [ ] Rough spots that block go into the batch before the feature. Others go into the batch within
      the budget, or into Now/Next.
- [ ] The build runs the /polish procedure: contract, builder with STATUS, one auditor, verify with
      the stamp, `land.sh`. Phase 8 is skipped in favour of /product's report.
- [ ] `owner-notes.md` → *Led to: P-09*. The Done-log line has evidence and the audit tally.
- [ ] No question to the owner (nothing in this is a product decision).

Failure signals: a new screen invented for this; skipping the adjacency check; pushing without
`land.sh`.
